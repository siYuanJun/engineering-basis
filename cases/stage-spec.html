CASE 05 / 053D-STAGE-DECK

交付表达，复杂结构怎么讲清

3d-stage-deck 把“讲清楚一个系统”拆成可校验的结构：几层、每层一句职责、流程按什么顺序走。下面三个样例先过结构校验，再决定能不能生成舞台。

公开切片 ｜ 零依赖 ｜ 样例输出为 2026-11-24 本地实跑

01它解决什么

讲清一个系统，难的不是画图，是取舍。讲不清通常有三个原因：层数和内容对不上、流程节点对不上层、文案长到放不下。这些不是审美问题，是结构问题，可以先校验再生成。

  • 层数控制在 3–5：多了讲不完，少了讲不出接力
  • 每层一句职责，不超过 70 字，标签才放得下
  • 流程至少三步，每一步必须落在已经定义的层或团队上
  • 校验不过就不生成，避免做出一个“看起来复杂但说不清”的页面

02三个可复现的判定

样例 A · 五层结构完整PASS
python3 demos/stage-spec/spec_check.py demos/stage-spec/fixtures/pass.json
通过：5 层，4 个团队，9 步 exit 0

每层有 id、名称、一句话职责，九步流转全部落在已定义的节点上。结构成立，可以生成可拆层的舞台。

样例 B · 流程指向不存在的层FAIL
python3 demos/stage-spec/spec_check.py demos/stage-spec/fixtures/broken-flow.json
警告：层 service 没有出现在流程里，讲解时会显得多余 错误：第 3 步 at 指向不存在的节点：unknown-layer 未通过：1 个错误 · exit 1

第三步指向一个没定义过的节点。页面上光点会走到空白处，讲解到这一步就断了。这类错误必须先修结构，不能靠临场发挥补。

样例 C · 两层，标题过长PASS · 2 提醒
python3 demos/stage-spec/spec_check.py demos/stage-spec/fixtures/thin.json
警告：title 超过 24 字（26），标题区会挤 警告：层数 2，建议 3–5 层 通过：2 层，0 个团队，3 步 · exit 0

两层也能生成，但讲不出“接力”这件事，标题也会挤成两行。校验给提醒，不阻断——结构完整性和表达效果是两件事，前者硬拦，后者提醒。

03规则是脚本拦截

“每层一句话”“流程要闭环”写在文档里，做的时候很容易被内容撑破。这里把错误和提醒分开：结构错误直接阻断生成，表达问题只提示，交给人判断。

类型例子处理
错误缺标题、层缺 id 或职责、流程少于三步、流程指向不存在节点阻断，不生成
提醒标题超长、层名过长、层数偏少或偏多、团队人数过多提示，可继续

04判据与边界

维度口径
判什么这份结构能不能讲清：层、职责、流程、文案
什么时候算过层数 3–5；每层有 id、名称、一句话职责；流程 ≥3 步且每步落在已有节点
什么时候停手流程引用不存在节点、层缺职责、缺标题
提醒但不拦标题与层名过长、层数偏少、团队人数过多
职责范围校验结构与文案；业务对错由人判断

执行方式：本地运行，Python 3 直接跑；输入为一份 JSON 结构；退出码 0 = 通过，1 = 有错误。
